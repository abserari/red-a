# 数据获取优化说明

## 优化后的数据获取流程

### 1. 历史价格数据优化

#### 智能缺失检测
- `get_missing_date_ranges()` 方法会检查数据库中已有的数据，找出缺失的日期段
- 只对缺失的日期段发起 API 请求，避免重复获取

#### 批量插入优化
- 获取数据后，先查询哪些日期的数据已存在
- 只插入不存在的新数据，使用 `insert_many()` 批量插入
- 避免了对已存在数据的不必要 update 操作

#### 性能提升
- 减少了 API 调用次数（只获取缺失数据）
- 减少了数据库写操作（只插入新数据）
- 使用批量插入代替逐条 upsert

### 2. 分红数据处理

#### 更新策略
- 分红数据采用"全量替换"策略：删除旧数据，插入新数据
- 设置更新周期（默认30天），避免频繁更新
- 分红数据量少，全量替换不影响性能

### 3. 使用建议

#### 首次运行
```bash
# 获取所有股票8年数据
uv run get_data_sequential.py
```

#### 日常更新
```bash
# 智能更新，只获取缺失数据
uv run get_data_sequential.py

# 更新分红数据（每周）
uv run get_data_sequential.py --dividend-days 7
```

#### 强制更新
```bash
# 强制更新所有数据（慎用）
uv run get_data_sequential.py --force
```

## 性能对比

### 优化前
- 每次都执行 update_one 操作，即使数据已存在
- 4000只股票 × 2000条数据 = 800万次 update 操作

### 优化后
- 首次运行：批量插入新数据
- 后续运行：跳过已有完整数据的股票
- 大幅减少数据库写操作

## 注意事项

1. **索引优化**：确保 (stock_code, date) 有复合索引
2. **批量大小**：insert_many 的批量大小受 MongoDB 限制（16MB）
3. **错误处理**：批量插入失败时会降级为逐条插入
