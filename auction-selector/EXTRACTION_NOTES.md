# 抽取说明（EXTRACTION_NOTES）

本项目相对原系统（基于付费 ashareapi 的集合竞价选股系统）的
保留与修改清单。策略公式为按原系统语义的自有重写实现，
未整包复制原代码。

## 保留（语义与数值口径一致）

- 配置阈值与权重全部沿用原 `config/settings.py`：
预过滤（5 日均额 ≥500 万、昨收 ≥2 元、K 线 ≥20 日、
距 30 日高点回撤 ≤30%、5 日均换手 ≥0.3%、池上限 300、
排序权重 0.4/0.3/0.2/0.1）、硬过滤（涨幅 1.5%–5.5%、
量比 ≥3、竞价额主板 ≥500 万/双创 ≥300 万、
撤单率 >0.6 且涨幅 <3% 剔除）、二阶段撤单率 >0.7 剔除、
打分权重（量比 0.35 / 竞价额 0.30 / 封单比 0.25 / 涨幅 0.10）、
板块联动加分系数 0.01、输出主板 Top10 / 双创 Top5、
初筛涨幅 ≥1% 与量比排序取前 30 的三阶段流程结构。
- 三个竞价序列因子的公式与原 `core/auction_factors.py` 完全
一致（自检逐项对照，误差 <1e-6）：
- 撤单率 = (09:15–09:20 段最大累计量 − 09:20 时刻累计量)
/ 段最大累计量（下限 0）
- 抢筹斜率 = 09:20–09:25 段指示价对时间的最小二乘回归斜率
- 尾盘加速度 = 最后 60 秒段的回归斜率
- 竞价量比上限 50、竞价额（量×撮合价）兜底算法、撮合价口径
（open 优先、无效回退现价）、板块联动公式
（同板块涨幅 >2% 占比 ×10 + 涨停先锋 2 分，上限 15）、
打分百分位口径（集合内严格小于占比）均与原系统一致。
- 候选池文件与输出文件的命名与大体结构沿用原约定
（prefilter_YYYYMMDD.json / recommendations_YYYYMMDD.json /
报告文本），便于对照。

## 修改

1. **数据源层全新抽象**：原系统策略与 ashareapi 客户端深度
耦合（引擎直接构造 API 客户端）。本项目定义 `DataProvider`
接口，策略核只依赖规范化结构；当前实现为腾讯公开接口。
2. **竞价序列改为自采**：原系统由付费 API 提供 09:15–09:25
竞价分时；本系统用快照轮询自采（15 秒粒度）拼序列。
3. **量比分母**：原系统恒用「5 日日均量 ×5%」近似。
本系统优先用自采积累的近 5 日竞价成交量均值；回退时带
`vol_ratio_fallback` 标记并在报告中注明口径。
4. **删除模拟价格序列**：原系统 `_simulate_price_series`
在无竞价数据时编造序列计算斜率。本系统一律记缺失（None），
且明确了缺失处理：打分四因子不依赖序列，故不剔除股票；
撤单率过滤在缺失时不触发；结果以 `has_auction_data` 标记。
5. **委买封单比改用买一量代理**：原 API 的买一未匹配量在
其批量行情里实际恒为 0（该因子在其自家输出中从未生效）；
本系统用 09:25 快照买一量作代理，该因子真实参与打分。
6. **板块联动暂缺**：原系统用 API 的 industry 字段建映射；
腾讯无此数据，映射为空、联动恒为 0（打分权重中仅 0.01
系数的加分项，影响可控）。接口位置已留好。
7. **去掉外围组件**：未移植原系统的 FastAPI 服务、Streamlit
前端、SQLite、板块/概念标签（产业链接口）与回测配置——
均为展示/外围功能，与选股核无关；需要时可后加。
8. **运行模式收敛**为 refresh / prefilter / morning /
selftest 四种；morning 增加交易时段守卫，非交易时段
明确报错退出，杜绝盘后用收盘快照假跑。
9. **日 K 缓存改为单文件 CSV + 增量合并**（原系统为逐只
CSV/pkl 缓存 + 独立基准数据文件）；基准量（5 日均量/
均额/昨收）在 prefilter 阶段一并算入候选池记录，
morning 直接取用，不再单独维护 benchmark 文件。
10. **股票池来源**：由 API 股票列表改为按代码段枚举 +
腾讯批量快照校验（与本机已验证的动量扫描同路径），
单批 ≤100 只、GBK 解码、直连失败自动回退家里中转代理。

## 未移植的原系统已知问题（记录备查）

- 原系统阶段1 在拿到真实竞价数据前先用模拟序列算一遍因子
再硬过滤，可能误杀/误放；本系统阶段1 只用快照因子
（斜率类因子在原打分中本就权重为 0），无此问题。
- 原系统 `FILTER_CRITERIA` 中的 20 日均额/换手两项在
Scorer 中实际未被引用，本系统同样未启用（保持口径一致，
在此注明而非悄悄改行为）。
